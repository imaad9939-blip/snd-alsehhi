# موقع سند الصحي – مركز صلاحيات المدير ولوحة المشرفين

موقع عربي كامل RTL يفتح على كامل عرض الكمبيوتر ويتجاوب مع الجوال، ويعمل بخادم Node.js وقاعدة بيانات SQLite محلية دائمة. لا يحتاج إلى تنزيل مكتبات خارجية؛ يحتاج Node.js **22.13 أو أحدث** لدعم الوحدة المضمنة `node:sqlite` (لاحظ أنها تجريبية في إصدارات Node 22).

## تشغيل الموقع على جهازك

1. فك الضغط عن الحزمة.
2. افتح موجّه الأوامر في المجلد الرئيسي (الذي يحتوي `server.js`).
3. شغّل `npm start` أو `node server.js`.
4. افتح المتصفح على **http://127.0.0.1:3000**.

اسم الدخول الابتدائي للمدير: `admin`. كلمة المرور هي التي حددتها في المحادثة. يتم حفظ **تجزئة** كلمة المرور في قاعدة البيانات، وليس نصها. غيّر كلمة المرور من **حسابي** بعد أول دخول.

إذا أردت تخصيص كلمة مرور المدير **قبل أول تشغيل لقاعدة جديدة فقط**، عرّف متغير البيئة `ADMIN_INITIAL_PASSWORD` بقيمة مناسبة. تغيير المتغير بعد إنشاء الحساب لا يعيد تعيين كلمة المرور تلقائيًا.

## الأقسام

- المدير العام: يرى جميع الوحدات ويمتلك جميع الصلاحيات في الخادم على الإضافة والتعديل والأرشفة والموافقة والرفض والإحصائيات والتصدير والمحتوى والإعدادات وإنشاء وإيقاف المشرفين.
- المشرفون: يعينهم المدير من صفحة «إدارة المشرفين»، ويمنح لكل منهم صلاحيات منفصلة؛ مثل استعراض الطلبات، تسجيل التوصيات، الموافقة النهائية، تعديل المستفيدين أو إدارة المحتوى. لا يستطيع أي مشرف تغيير مدير النظام أو مشرف آخر.
- المستفيد: يقدم طلب العضوية بأربع خطوات ويرفع إثبات الهوية والتقرير الطبي. يبقى طلبه **قيد المراجعة**، ويمكنه تسجيل الدخول فقط لمعرفة حالة الطلب والإشعارات وتحديث بياناته الشخصية. لا تظهر البطاقة ولا العروض حتى اعتماد العضوية.
- موافقة الإدارة: المشرف المخوّل يراجع ويقدم التوصية، ثم يعتمد المدير النهائي. المدير يستطيع تجاوز مراجعة المشرف بذكر سبب واضح يُسجّل في سجل العمليات. لا يستطيع المستفيد تفعيل حسابه.
- العروض والشركاء والإعلانات: تدعم الإضافة والتعديل والإخفاء والحذف، ولا تظهر إلا للمستفيدين النشطين.
- الإحصائيات: أعداد العضويات والطلبات والمشرفين والتوزيع الصحي وتصدير CSV.
- السجل: يسجّل عمليات اعتماد العضوية والإدارة والتعديل والتصدير.


## إدارة الصلاحيات من داخل حساب المدير

بعد تسجيل الدخول باسم `admin` ينتقل المدير إلى **لوحة تحكم المدير**. يفتح قائمة **حسابي**، ثم يضغط **فتح صفحة الصلاحيات** لينتقل إلى **مركز صلاحيات المدير والمشرفين**. هذه الصفحة للمدير فقط، وفيها:

- عرض صلاحيات `admin` الكاملة غير القابلة للتعطيل من المشرفين.
- **تعيين مشرف جديد** مع كلمة مرور واسم مستخدم ورقم جوال.
- بطاقات بكل المشرفين، مع تقسيم الصلاحيات إلى الطلبات والمستفيدين والمحتوى والإحصائيات، وحفظ ما مُنح لكل مشرف مباشرة في الخادم.
- تعديل بيانات المشرف أو إيقافه من مركز الصلاحيات أو صفحة **المشرفون**.

عند دخول المشرف بحسابه تظهر له **لوحة تحكم المشرف**، مع أدوات الإدارة التي فوّضه المدير باستخدامها فقط. إن لم يمنحه المدير صلاحية الإحصائيات تظل لوحة المشرف متاحة دون كشف البيانات الإحصائية. كما تعرض صفحة **حسابي** للمشرف قائمة صلاحياته للقراءة فقط؛ لا يستطيع تعديلها أو الوصول إلى مركز الصلاحيات.

صلاحيات المشرف محفوظة في قاعدة البيانات ويفحصها الخادم عند كل عملية، وتُحدّث في الجلسات الفعالة عند الانتقال بين الشاشات. منح صلاحية تعديل بيانات يتضمن تلقائيًا صلاحية قراءة البيانات المقابلة حتى تعمل صفحة الإدارة.

## الاستضافة على الإنترنت

لا تستطيع ملفات ZIP وحدها إنشاء رابط عام. تحتاج لاستضافة تشغّل Node.js طوال الوقت مع **قرص دائم** لقاعدة البيانات والملفات. من الخيارات خادم افتراضي VPS أو منصة تدعم خادم Node.js مع تخزين دائم. لا تصلح استضافة HTML ثابتة وحدها لهذا المشروع.

- اضبط `HOST=0.0.0.0` و`PORT` وفق متطلبات الاستضافة.
- احفظ `DATA_DIR` و`UPLOAD_DIR` على تخزين دائم خاص (لا تضعهما داخل مجلد `public`).
- وفّر عنوان HTTPS حقيقيًا بشهادة TLS، واضبط `COOKIE_SECURE=true` خلف خادم وسيط موثوق.
- لا ترفع ملفات المرضى أو الهويات الحقيقية حتى إتمام إجراءات الأمان والامتثال الرسمية ومراجعة إدارة الصلاحيات وحماية الملفات والنسخ الاحتياطية.
- إن نشرت عبر Docker، يمكن استخدام Dockerfile المرفق وربط مجلدَي البيانات والرفع بوحدات تخزين دائمة، وتوجيه المرور عبر خادم HTTPS.

## حدود النسخة

هذه نسخة أولية قابلة للتجربة والتطوير وليست نظامًا طبيًا معتمدًا. لا تتضمن تحققًا رسميًا من الهوية أو الرقم الوطني، ولا إرسال SMS/Email أو تكاملًا مع بوابة دفع، ولا يتم تحصيل مبلغ العضوية المميزة (20 ريالًا معروض للخطة فقط). البطاقة الرقمية تعرض رقم العضوية، **لا تتضمن رمز QR رسميًا قابلًا للتحقق** حتى بناء خدمة التحقق. تخزين SQLite وتطبيق Node يحتاجان مراجعة أمان وتشغيل ونسخ احتياطية قبل الإنتاج الحقيقي. الاستضافة المباشرة لم تكن متاحة تلقائيًا في هذه المحادثة بسبب اشتراط اشتراك نشط بخدمة النشر.

## الملفات

- `server.js`: الخادم، إدارة الجلسات، الموافقات، قاعدة البيانات، وحفظ الملفات الخاصة.
- `public/index.html`, `public/styles.css`, `public/app.js`: واجهة الموقع كاملة بعرض الصفحة.
- `public/assets/`: شعار سند الصحي المقتبس من الصور المرفقة.
- `data/`: قاعدة البيانات التي ينشئها الخادم عند التشغيل (خاص، لا تنشره).
- `private_uploads/`: المرفقات الخاصة (لا تُعرض إلا للمخولين).

مهم: حافظ على نسخ احتياطية مشفرة من قاعدة البيانات والملفات، ونظّم الاحتفاظ والحذف وفق سياسة الخصوصية المعتمدة للجهة.

## نسخة المعاينة المستقلة

يتوفر كذلك ملف منفصل للمعاينة باسم `sanad-health-permissions-preview.html` يُفتح بالمتصفح مباشرة ويُحاكي تسجيل الدخول وإدارة الصلاحيات دون تشغيل الخادم. بياناته تجريبية ومخزنة في المتصفح، وهي **ليست** النسخة الآمنة للاستخدام الفعلي.

بيانات اختبار المشرف للمعاينة فقط: `supervisor_demo` وكلمة مرور `Supervisor@123`. هذا الحساب **غير موجود** تلقائيًا في نسخة الخادم؛ ينشئه المدير بنفسه عند الحاجة. تجنب إدخال أو رفع أي بيانات طبية حقيقية في ملف المعاينة.
